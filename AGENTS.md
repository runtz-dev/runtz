# Working in this repository (humans and AI agents)

This file is the contract for anyone — human or AI coding agent (Claude, Codex,
...) — sending changes to runtz. Agents: read this before opening a pull request.

## Repository layout

- `engine/` — Go backend engine (module `github.com/runtz-dev/runtz/engine`).
- `frontend/` — Next.js web platform.
- `helm/` — Helm chart (`helm/runtz`) and our own environment overlays
  (`helm/environments/{dev,prod}`).
- `.github/workflows/` — dev/prod pipelines and release drafter.

The scanner CLI is **not** here — it lives in
[runtz-dev/runtz-cli](https://github.com/runtz-dev/runtz-cli). The MCP server is
in [runtz-dev/runtz-mcp](https://github.com/runtz-dev/runtz-mcp). The VS Code
extension is in
[runtz-dev/runtz-vscode-extension](https://github.com/runtz-dev/runtz-vscode-extension).

## Branch and release flow

```
feature branch ──▶ dev ──▶ main
   (your work)     (dev env)   (prod, on release publish)
```

- Branch off `dev`. Open pull requests **against `dev`**.
- `dev` auto-deploys to the dev environment (runtz-dev.runtz.dev).
- Releases promote `dev → main`; publishing a GitHub Release for the tag
  builds the public images, pushes the Helm chart and deploys prod.
- Never push straight to `main` for feature work.

## Checks to run before opening a PR

```bash
cd engine && go test ./... && go vet ./...
cd ../frontend && npm run lint && npm run build   # if the frontend changed
helm lint helm/runtz                              # if the chart changed
```

Keep changes scoped and match existing patterns in each package.

## Hard rules

- **Never commit secrets, tokens, kubeconfigs or personal endpoints.** Real
  secrets live only in the cluster (Kubernetes Secrets) and in GitHub
  Actions secrets/vars — never in the repo. `values.secrets.yaml` and `.env`
  are gitignored; keep it that way.
- **Do not touch paid-plan license enforcement to unlock features.** The
  Ed25519 verification in `engine/internal/api/license.go` and the compiled-in
  key in `engine/internal/config/config.go` are load-bearing. See
  [NOTICE](NOTICE); weakening them breaches the license.
- Update docs (README / site) when behavior changes.

## Pull requests

Fill the **Generated by** section of the pull request template. If an agent
wrote the change, name the agent and model, the task it was given, and how the
change was verified (tests run, app exercised). A human must review the full
diff and is accountable for it.
